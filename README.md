# HalfShell

뚜껑을 **연 채로** 내장 디스플레이만 끄고 외장 디스플레이를 단독 사용하게 해주는 macOS 메뉴바 앱.
클램쉘 모드의 화면 구성은 그대로 가져오면서, 뚜껑을 닫아서 생기는 발열 문제를 피한다.

> **이름에 대하여.** 클램쉘(clamshell)은 조개껍데기, 즉 **뚜껑을 닫은** 상태를 가리킨다.
> 이 앱이 만드는 것은 화면 구성만 같을 뿐 물리적으로는 정반대다 — 오히려 뚜껑을 닫지
> **않는 것**이 존재 이유다(닫으면 방열이 나빠진다). 그래서 "반만 열린 조개"라는 뜻의
> HalfShell 로 부른다. 클램쉘 계열임을 알리면서 닫지 않았다는 차이를 담기 위해서다.

## 기능

- **자동 모드**: 켜두면 외장 디스플레이가 감지될 때 내장 디스플레이를 자동으로 끈다.
- 외장 디스플레이가 모두 분리되면 **자동 모드와 무관하게 내장을 즉시 복구**한다 (화면이 하나도 없는 상태 방지).
- 메뉴바에서 수동으로 끄기/켜기 가능. 수동으로 켜면 자동 모드도 함께 꺼진다.
- 앱을 종료하면 내장 디스플레이가 복구된다. 강제 종료(크래시 포함)되어도 OS가 자동으로 되돌린다(아래 참고).
- 로그인 시 자동 실행 옵션.

### 복구 규칙

우선순위가 높은 것부터 적용된다.

1. **외장이 하나도 없으면 무조건 내장을 켠다.** 다른 모든 규칙을 무시한다.
   화면이 하나도 없어서 조작 자체가 불가능해지는 상황을 막는 최후의 방어선.
2. 자동 모드가 꺼져 있으면, 이번 세션에서 사용자가 직접 끈 게 아닌 한 내장을 켠다.
   이전 인스턴스가 크래시했거나 다른 앱(Lunar 등)이 꺼둔 상태를 자가 치유한다.
3. 자동 모드 + 외장 존재 → 내장을 끈다. **단, 무장 상태일 때만.**

**뚜껑이 닫혀 있으면 위 규칙 1·2 는 적용하지 않는다.** 뚜껑을 닫아서 내장이 꺼진
것은 정상적인 클램쉘이지 고쳐야 할 상태가 아니다.

### 뚜껑을 닫으면 (클램쉘)

평범하게 클램쉘로 들어간다. 이 앱은 아무것도 하지 않는다.

내장 디스플레이가 꺼지는 이유는 네 가지인데, macOS 가 주는 재구성 알림만으로는
서로 구분되지 않는다 — 뚜껑을 닫아서 꺼진 것과 다른 앱이 끈 것이 **완전히 같은
모양**으로 보인다. 그래서 `IOPMrootDomain` 의 `AppleClamshellState` 를 따로 읽어
구분한다. 터미널에서도 같은 값을 볼 수 있다.

```sh
ioreg -r -k AppleClamshellState -d 4 | grep AppleClamshellState
#   "AppleClamshellState" = No     ← 열림
```

이 구분이 없던 동안에는 뚜껑을 닫아도 앱이 내장을 계속 되살려서 클램쉘로 들어가지
못했다(사건 5). 보이지 않는 화면이 배치에 남아 **창이 그쪽으로 끌려가는** 문제가
있었다.

값을 읽지 못하면 **"열림"으로 간주한다.** 반대로 틀리면 화면 복구가 막혀 사용자가
검은 화면에 갇히기 때문이다. 뚜껑이 없는 Mac(mini·Studio·Pro)에는 이 값 자체가
없으므로 자연히 "열림"이 된다.

**화면 복구 단축키와 메뉴의 "내장 디스플레이 켜기"는 이 검사를 건너뛴다.**
상태 판단이 어떤 이유로든 어긋났을 때 탈출까지 함께 막히면 안 되기 때문이다.

### 잠든 맥에 독을 꽂았는데 외장에 화면이 안 나온다면

**정상이다.** 덮인 채 잠든 맥에 독을 꽂으면 macOS 는 **속으로만 깨어나고**(DarkWake)
화면은 켜지 않는다. 케이블은 이미 연결됐지만 macOS 가 외장을 아직 구동하지 않은
상태다. **외장 키보드의 아무 키나 누르거나 마우스를 움직이면**(또는 뚜껑을 열면)
화면이 들어온다. Apple 의 클램쉘 안내도 같은 순서다. HalfShell 은 이 단계에 관여하지
않는다 — 뚜껑이 닫혀 있으면 내장은 이미 macOS 가 꺼 둔 상태다.

블루투스 키보드를 다른 채널로 돌려 두었다면 키를 눌러도 이 맥에 닿지 않으니,
마우스나 뚜껑으로 깨운다.

### 잠자기·깨어남에서의 예외

잠들기 직전에 내장을 되돌려 놓고, **잠들기 전환 중(60초)에는 규칙 판단 자체를
쉬며**, **깨어난 직후에는 관찰만으로 내장을 다시 끄지 않는다.** 전환 중의
디스플레이 목록은 낡은 값일 수 있고, 그 순간 발행한 커밋은 잠든 WindowServer 에
붙잡혀 맥이 깨어날 때까지 돌아오지 않기 때문이다(사건 6 — 메인 스레드가 17분
정지했다). 깨어남 복구도 뚜껑이 닫혀 있으면 클램쉘로 보고 조용히 중단한다.

깨어날 때 조심하는 이유는 유령 때문이다. macOS 가 저장된 배치를 복원하면서 실제로는 연결되지 않은
디스플레이를 활성 목록에 올리는데, 그 껍데기는 직전 모니터의 vendor·model·해상도를
그대로 물려받아 **화면 목록만으로는 진짜와 구분할 방법이 없기 때문이다**(사건 3).

### 유령과 진짜를 가르는 법 — 물리 링크

**목록 밖에 독립된 증거가 있다.** Apple Silicon 의 디스플레이 코프로세서(DCP)는
전기적으로 살아 있는 케이블 링크마다 기록을 남기는데, 유령은 macOS 의 기억이
만든 것이라 이 기록이 없다. 한 달간 기록만 하며 검증한 결과, 깨어날 때 나타난
유령 세 마리는 전부 물리 링크 0, 진짜 모니터는 링크 수가 맞았다(사건 7).

그래서 지금은 이렇게 동작한다.

- **깨어날 때 외장이 물리 링크로 확인되면** — 내장을 되살리지 않고 바로 자동 끄기를
  재개한다. 독에 꽂힌 채로 깨워도 내장이 꺼진 상태를 유지한다.
- **규칙 3이 내장을 끄기 전에** — 목록의 외장이 물리 링크로 뒷받침되면 즉시 끄고,
  아니면 같은 구성이 15초 유지될 때 끈다. 유령은 1초 안에 사라지므로 걸리지 않는다.

**DisplayLink 독, AirPlay, Sidecar** 화면은 DCP 를 거치지 않아 장부에 잡히지 않는다.
이런 화면만 쓰는 경우 자동 끄기가 **15초 늦게** 동작한다. **Intel Mac** 은 이 장부가
없어서 예전 방식 그대로다.

### 장부로 확인되지 않을 때 — 예전 방식

자동 끄기는 다음 중 하나가 있어야 다시 무장된다.

- 외장이 물리 링크로 확인됨 (위)
- 외장이 0개인 상태를 한 번 지나감 (= 다음에 붙는 것은 진짜 연결)
- 깨어난 지 5초가 지난 뒤의 디스플레이 추가 이벤트
- 사용자의 명시적 조작(메뉴에서 끄기, 자동 모드 다시 켜기)

**대가**: 장부가 없는 Intel Mac 이나 DisplayLink 만 쓰는 구성에서는, 독을 꽂은 채
깨우면 내장이 함께 켜진 채 남을 수 있다. 메뉴의 "내장 디스플레이 지금 끄기"를
한 번 누르면 된다. 검은 화면으로 깨어나는 것보다 낫다는 판단이다.

내장이 켜질 때 **메인 화면(메뉴 막대)까지 내장으로 따라오는 것**이 거슬린다면:
세 화면이 모두 켜진 상태에서 시스템 설정 → 디스플레이에서 메인을 외장으로
옮겨두면 된다. macOS 가 그 디스플레이 조합의 배치로 기억해서, 이후로는 내장이
켜져도 메인이 외장에 남는다(실측 확인).

감시 경로를 여러 겹으로 둔다. `CGDisplayRegisterReconfigurationCallback`(가장 빠름),
AppKit 화면 변경 알림, 메인 큐 워치독, 그리고 **`SafetyNet`**.
(AppKit 알림은 Dock 이 숨거나 전체화면 전환만 해도 오므로 — 실측 153회 중 실제
디스플레이 변화는 36회 — 판단 계기로만 쓰고 로그에는 남기지 않는다.)

`SafetyNet` 이 규칙 1 전용 최후 방어선이다. 화면이 0개가 되면 이 앱은 창도 입력도
없는 완전한 백그라운드 프로세스가 되어 **App Nap 이 메인 런루프 타이머를 수십 초씩
지연**시킬 수 있다. 그래서 `SafetyNet` 은 전용 큐의 `DispatchSourceTimer` 를 쓰고
판단과 복구를 그 큐에서 끝낸다(MainActor 를 거치지 않는다). App Nap 자체도
`ProcessInfo.beginActivity` 로 막는다. 평상시 5초 주기로 돌다가, 재구성이 감지되면
6초 동안 0.1초 주기로 좁힌다.

### 화면 복구 단축키 (Command 연타)

자동 복구가 어떤 이유로든 실패했을 때 **화면이 보이지 않는 상태에서** 손만으로
빠져나오는 마지막 수단이다. **Command 키만 4초 안에 5번** 누르면 내장 디스플레이를
켜고 자동 모드를 끈다. 자동 모드를 함께 끄는 것이 중요하다 — 켜기만 하면 규칙 3이
곧바로 다시 꺼버려서 "눌러도 안 된다"가 된다.

오발 방지: **Command 를 누른 채로 다른 키가 눌리면** 카운트를 버린다. 그것이
단축키(Cmd+C, Cmd+Tab 등)이기 때문이다. 반대로 Command 를 뗀 사이에 들어온 키는
연타와 무관하므로 무시한다 — 당황해서 두드릴 때 손이 다른 키를 스치는 것까지
실패로 처리하면 정작 필요한 순간에 걸리지 않는다(실측으로 확인).

전역 키 모니터라 **손쉬운 사용 권한**이 필요하다. 모든 키 입력을 볼 수 있는 능력이라
macOS 가 기본적으로 막아두기 때문이다. 권한이 없으면 조용히 꺼진 채로 남고 메뉴에
그 사실이 표시된다. **이 기능은 끌 수 없다** — 화면을 잃었을 때 손만으로 빠져나올
수 있는 유일한 수단이라, 실수로 꺼둘 여지를 두지 않는다.

허용하는 곳은 **시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용**이다. 이름이 같은
"시스템 설정 → 손쉬운 사용"은 VoiceOver 같은 *기능* 설정이라 그쪽이 아니다.
기능을 처음 켤 때 macOS 가 띄우는 대화상자의 "시스템 설정 열기"를 눌러도 된다.
허용하면 앱을 다시 시작하지 않아도 2초 안에 스스로 붙는다.

> 주의: 서명이 바뀌면 macOS 가 다른 앱으로 보아 권한이 풀린다. ad-hoc 서명은
> 재빌드마다 해시가 바뀌므로 **권한이 아예 유지되지 않는다**(사건 3-B). 그래서
> `build.sh` 는 정식 인증서를 우선 사용한다. 그래도 번들 ID 가 바뀌면 재등록이
> 필요하니, 업데이트 후 메뉴에 "작동 안 함"이 보이면 목록에서 지웠다가 다시 추가한다.

### 오류 신고와 자동 보고

사용자가 **앱 안에서 바로 신고**할 수 있다(정보 창 → 오류 신고하기). 무슨 일이
있었는지 적고 보내면 끝이고, **보내기 전에 함께 나가는 정보를 펼쳐 볼 수 있다.**

GitHub 이슈를 앱이 직접 만들려면 쓰기 토큰이 필요한데 배포본에 심으면 누구나
꺼내 쓸 수 있다. 그래서 이미 붙어 있는 Sentry 를 통로로 삼았다 — 토큰도 서버도
필요 없다. 자동 전송을 꺼둔 사용자를 위해 브라우저로 이슈를 여는 경로도 남겼다.

#### 자동 보고 (Sentry)

크래시는 SDK 가 알아서 수집한다. 문제는 **지금까지 겪은 네 번의 사고가 모두 크래시가
아니었다**는 점이다 — 앱은 멀쩡히 살아서 잘못된 판단을 내리고 화면을 검은 채로 뒀다.
그래서 자동 수집에만 기대면 정작 중요한 사고를 하나도 못 잡는다. 크래시 수집은
그대로 두고, 우리가 사고라고 판단한 것을 **추가로** 보낸다. 넷뿐이다.

| 사건 | 왜 |
| --- | --- |
| 깨어난 뒤 내장 복구 재시도 소진 | **화면이 검은 채로 남았다는 뜻.** 그 순간 사용자는 신고할 방법이 없다 |
| 안전망 복구 5회 연속 실패 | 최후 방어선이 무너지는 중 |
| SkyLight 심볼 없음 | macOS 업데이트로 Apple 이 끊었다는 신호. 신고를 기다리면 늦다 |
| 느린 커밋이 5분 안에 5회 반복 | 배터리 사고의 신호. 한 번 느린 것은 흔하지만 **반복은 구조적 문제**다 |

흔한 일까지 보내면 진짜 사고가 묻히므로 의도적으로 좁혔다. 앱 멈춤(5초 이상)도
함께 수집한다 — SkyLight 커밋이 메인 스레드를 10초씩 잡는 것을 실측했기 때문이다.

DSN 은 `Resources/Info.plist` 의 `SentryDSN` 에서 읽는다. **비어 있으면 통째로
비활성**이라, 값을 넣지 않은 빌드는 아무것도 전송하지 않는다.

> DSN 은 **쓰기 전용 공개 키**다. 클라이언트 앱에 심으라고 만들어진 것이라
> 저장소가 공개돼도 정상이며, 이것으로 남의 데이터를 읽을 수는 없다.
> 다만 아는 사람은 **가짜 이벤트를 보내 할당량을 소모시킬 수 있다.**
> 그런 일이 생기면 Sentry 설정에서 키를 폐기하고 새로 발급하면 된다.

사용자는 정보 창에서 끌 수 있다. 로그 본문이나 신원 정보는 보내지 않는다.

### 로그

`~/Library/Logs/HalfShell.log` 에 기록한다. 메뉴바 → **HalfShell 정보 보기** 창의 "로그 열기"로도 열 수 있다.
화면이 하나도 없는 순간에 무슨 일이 있었는지는 사후에 로그로만 확인할 수 있어서,
디스플레이 재구성 이벤트와 복구 시도를 모두 남긴다.

## 언어

**맥의 시스템 언어를 따라갑니다.** 한국어면 한글, 그 밖에는 영어로 뜹니다.
앱 안에 언어 설정은 두지 않았다 — macOS 표준 동작이라 사용자가 기대하는 곳
(시스템 설정 → 일반 → 언어 및 지역)에서 이미 정할 수 있기 때문이다.

바꾸지 않고 한 번 확인해 보려면:

```sh
/Applications/HalfShell.app/Contents/MacOS/HalfShell -AppleLanguages '(en)'
```

**진단 로그는 번역하지 않는다.** [POSTMORTEM.md](POSTMORTEM.md) 의 사건 분석과
"재발 시 진단 순서"가 `[규칙2] 자가 치유` 같은 한글 로그 줄을 그대로 인용하고
있어서, 옮기면 지금까지 쌓은 진단 대조표가 통째로 어긋난다. 로그는 개발자용
자료이므로 사용자가 읽을 일도 드물다.

번역을 고치거나 언어를 추가하려면 `Resources/<언어>.lproj/Localizable.strings`
하나만 만들면 된다. **키가 한글 원문이라 번역이 빠진 항목은 한글로 떨어진다** —
빈 화면이 뜨는 일은 없다.

## 지원 환경과 주의사항

배포 전에 반드시 읽어야 할 부분이다.

| 환경 | 동작 |
| --- | --- |
| **MacBook (Apple Silicon), macOS 13+** | 정상 동작. 실제로 검증된 조합 |
| **Mac mini / Studio / Pro** | 내장 디스플레이가 없어 **할 수 있는 일이 없다.** 앱은 실행되지만 메뉴에 그 사실을 표시하고 모든 기능을 잠근다 |
| **Intel Mac** | 유니버설 바이너리라 실행은 된다. 다만 **검증하지 못했다** — SkyLight 동작이 다를 수 있다. 비공개 심볼이 없으면 기능만 꺼지고 크래시하지는 않는다 |
| **macOS 12 이하** | 실행 불가 (`MenuBarExtra`·`SMAppService` 가 13+ 요구) |

그 밖에 사용자에게 반드시 알려야 할 것들:

- **Lunar / BetterDisplay 와는 겹치는 기능만 끄면 된다** (아래 참고). 앱을 지울
  필요는 없다.
- **비공개 API 를 쓴다.** macOS 메이저 업데이트 후에는 동작을 다시 확인해야 한다.
  심볼이 사라지면 기능이 비활성화될 뿐 크래시하지는 않는다.
- **Gatekeeper 차단.** 아직 공증 전이라 다른 맥에서는 처음 실행 시 막힌다 (아래 참고).
- **Mac App Store 에는 없다.** 비공개 API 와 샌드박스 때문에 올릴 수 없다 — 이유와
  대신 택한 배포 방식은 [DISTRIBUTION.md](DISTRIBUTION.md).
- **손쉬운 사용 권한**은 Command 연타 화면 복구 단축키에만 필요하다. 허용하지 않아도
  자동 끄기·복구는 정상 동작한다. 다만 아래 이유로 **설치 직후 허용을 권한다.**

### 닫아서 들고 다닐 때 배터리가 많이 닳는다면

**대개 HalfShell 이 아니다.** 잠든 동안 HalfShell 은 로그를 몇 줄 남기는 것 말고는
아무것도 하지 않는다. 지금까지 실측한 원인은 둘이었다.

- **블루투스 키보드가 맥북에 연결된 채로 켜져 있음** — 1분마다 재연결을 시도하며
  맥을 깨운다(8/20~22, 하룻밤 7~15%). 덮기 전에 키보드를 끄거나 채널을 바꾸면 된다.
- **공항처럼 공용 WiFi 가 빽빽한 곳을 이동** — 잠든 동안 네트워크 연결을 유지하는
  기능(TCP Keep Alive)이 WiFi 변화마다 맥을 깨운다. 가방 속이라 열이 빠지지 못해
  과열 경고까지 났다(10/8, 8시간 반에 43%). 배터리일 때만 끄려면:

  ```sh
  sudo pmset -b tcpkeepalive 0     # 되돌리기: … tcpkeepalive 1
  ```

  대가로 **배터리로 잠든 동안 "나의 찾기"가 제대로 동작하지 않는다.** 설정을 바꾸고
  싶지 않으면 이동할 때 WiFi 를 끄는 것으로도 된다.

원인을 직접 보려면 `pmset -g log | grep "DarkWake from"` 에서 `due to` 뒤를 보면 된다.
`rtc` 는 예약된 깨움(Power Nap 등), `wifibt` 는 무선 칩이 무언가를 받아 깨운 것이다.

### Lunar / BetterDisplay 와의 충돌

전체가 충돌하는 것이 아니라 **같은 SkyLight API 를 쓰는 기능끼리만** 충돌한다.

| 기능 | 충돌 |
| --- | --- |
| Lunar 의 **BlackOut / Auto BlackOut**(Pro) | **충돌** — HalfShell 의 자동 모드와 완전히 같은 일을 한다 |
| BetterDisplay 의 **disconnect** | **충돌** |
| 밝기 조절, DDC 제어, 색온도, 프리셋 등 | 문제없음 |

충돌은 우연이 아니라 설계상 필연이다. HalfShell 의 규칙 2 는
"자동 모드가 꺼져 있는데 내장이 꺼져 있으면 켠다"인데, 이것은 다른 앱이 꺼둔
상태를 **적극적으로 되돌리도록** 만들어져 있다. 상대 앱도 같은 논리를 가지므로
서로 무한히 되돌린다.

실제로 재현해 본 결과: 상대 앱이 끄면 HalfShell 이 0.3초 안에 되살리고, 상대가
다시 끄는 일이 반복된다. 매 회 디스플레이 재구성이 일어나므로 **화면이 계속
깜빡이고, macOS 가 창을 옮기면서 창 배치가 흐트러지며**, 가상 디스플레이 ID 가
계속 새로 생기고(`display=30, 31, 32 …`), 충돌한 트랜잭션은 오류 1001 로 실패한다.

### 화면을 잃었을 때의 탈출 (사용자에게 반드시 안내할 것)

화면이 검게 남으면 **마우스도 터미널도 쓸 수 없다.** 그 상태에서 실제로 통하는
방법만 순서대로 안내해야 한다.

| 순서 | 방법 | 조건 |
| --- | --- | --- |
| 1 | **Command 4초 안에 5번 연타** | 손쉬운 사용 권한을 미리 허용해 둔 경우만 |
| 2 | **외장 디스플레이 케이블 재연결** | 항상 가능. 연결 즉시 복구 |
| 3 | 전원 버튼 길게 눌러 강제 재시작 | 최후 수단. `session` 범위 설정이 초기화된다. 저장하지 않은 작업은 사라진다 |

`pkill -x HalfShell` 은 **화면이 보이는 상태이거나 다른 Mac 에서 SSH 로 접속했을
때만** 쓸 수 있다. 검은 화면 앞에서는 입력할 방법이 없으므로 사용자 안내에
넣으면 안 된다. 진단 목적의 명령은 [POSTMORTEM.md](POSTMORTEM.md#재발-시-진단-순서) 참고.

## 설치

DMG를 받았다면 열어서 `HalfShell.app`을 **응용 프로그램** 폴더로 드래그한 뒤,
터미널에서 격리 속성을 한 번 풀어준다 (아래 [Gatekeeper](#gatekeeper) 참고):

```sh
xattr -cr /Applications/HalfShell.app
```

실행해도 창은 뜨지 않는다. 메뉴바 오른쪽에 노트북 아이콘이 생기고, 거기서
"외장 연결 시 내장 디스플레이 자동 끄기"를 켜면 된다.

## 빌드

### 시험

```sh
swift test
```

유령 판별·규칙 3의 관문·깨어남 복구 재시도의 판단 로직을 시험한다. 입력은
**실측 사례 그대로**다(9/5·9/11·9/19·10/24 유령, 10/14·10/22 진짜 모니터 등).
새 유령이나 새 실패가 관측되면 사례를 하나씩 더한다 — 다음 수정이 과거에 맞혔던
판정을 깨뜨리는지 바로 드러나게 하기 위해서다.


Xcode는 필요 없다. Command Line Tools의 Swift 툴체인만 있으면 빌드된다.

```sh
./build.sh      # build/HalfShell.app 생성 (아이콘 포함)
./install.sh    # 빌드한 앱을 /Applications 로 설치하고 실행
./make-dmg.sh   # 배포용 DMG 생성
```

요구사항: Apple Silicon, macOS 13+ (개발은 macOS 26 / M5에서 검증).

`install.sh`는 실행 중인 인스턴스를 먼저 종료한다. 이때 내장 디스플레이가 잠시
복구되었다가, 새로 실행된 앱이 자동 모드 설정에 따라 다시 끈다.

### 배포용 DMG

`./make-dmg.sh`는 `dist/HalfShell-<버전>.dmg`를 만든다. 버전은
`Resources/Info.plist`의 `CFBundleShortVersionString`에서 읽으므로, 버전을 올리려면
그 값만 수정하면 된다. 앱이 빌드되어 있지 않으면 `build.sh`를 먼저 호출한다.

DMG를 열면 세 가지가 보인다:

| 항목 | 용도 |
| --- | --- |
| `HalfShell.app` | 드래그할 앱 |
| `응용 프로그램` | `/Applications` 심볼릭 링크 (드래그 대상) |
| `먼저 읽어주세요.txt` | 설치 방법과 Gatekeeper 해제 안내 |

USB, AirDrop, 클라우드 등 아무 방법으로나 옮겨서 열면 된다.

### Gatekeeper

지금 빌드는 **개발용 인증서(Apple Development)로 서명만 되어 있고 공증은 받지 않았다.**
(8월 초에는 ad-hoc 서명이었다 — 손쉬운 사용 권한이 재빌드마다 풀려서 바꿨다, 사건 3-B.)
그래서 다운로드하거나 AirDrop으로 받은 경우 격리(quarantine) 속성이 붙어 macOS가
실행을 차단한다.
위의 `xattr -cr` 한 줄로 풀거나, 앱을 우클릭 → "열기" → 대화상자에서 다시 "열기"를
선택하면 된다. 한 번만 하면 이후로는 그냥 실행된다.

경고 자체를 없애려면 Developer ID 인증서로 서명하고 `xcrun notarytool`로 공증해야
한다 — 배포판은 이 방식으로 낸다([DISTRIBUTION.md](DISTRIBUTION.md)). 참고로 공증한
앱은 멤버십이 만료되어도 계속 동작한다(서명 시점의 타임스탬프로 검증하므로).

## 동작 원리

macOS에는 디스플레이를 활성 배열에서 제거하는 공개 API가 없다. 이 앱은 SkyLight
비공개 프레임워크의 디스플레이 구성 트랜잭션을 사용한다:

```
SLSBeginDisplayConfiguration(&config)
SLSConfigureDisplayEnabled(config, displayID, false)
SLSCompleteDisplayConfigurationWithOption(config, 0 /* forAppOnly */)
```

- 밝기 0이나 미러링 꼼수가 아니라 **논리적 disconnect**다. 내장 디스플레이가
  `CGGetActiveDisplayList`에서 사라지고, 창과 마우스가 그쪽으로 갈 수 없게 된다.
  BetterDisplay / Lunar의 disconnect 기능과 같은 계열의 방식.
- `forAppOnly`(옵션 0)로 커밋하므로 **이 프로세스가 종료되면 변경이 자동으로 되돌아간다.**
  앱이 죽어도 내장 디스플레이가 꺼진 채 남지 않는 핵심 안전장치.
- 심볼은 `dlsym`으로 런타임에 찾는다. OS 업데이트로 비공개 심볼이 사라지면 기능이
  비활성화될 뿐 크래시하지 않는다.

### 가상 디스플레이 함정

실제 패널이 하나도 활성 상태가 아니게 되면 **macOS 가 가상 디스플레이를 하나
만들어낸다.** 실측값은 이렇다.

```
id=11 builtin=false active=true online=true
vendor=1970170734 model=1986622068  1920x1080
```

vendor/model 이 숫자가 아니라 ASCII 4글자다 — `0x756E6B6E` = `"unkn"`,
`0x76697274` = `"virt"`. 그리고 `CGDisplayIsBuiltin` 이 **false** 다.

그래서 그냥 두면 외장 디스플레이로 오인된다. "외장이 있으니 내장은 꺼둬도 된다"고
판단해 버리므로, 정작 화면이 하나도 안 나오는 상황에서 복구가 영영 일어나지 않는다.
실제로 외장 케이블을 뽑았을 때 화면이 검은 채로 남던 원인이 이것이었다.
그래서 모든 판단은 가상 디스플레이를 걸러낸 `realActiveDisplays()` 로 한다.

또 하나 확인된 사실: 이 상태에서는 `appOnly` 커밋의 **자동 원복도 동작하지 않는다.**
앱을 강제 종료해도 내장이 돌아오지 않았다. 그래서 켜기는 `session` 범위로 커밋하고,
자동 원복에 기대지 않는다.

### 잠자기와 구분하기 (전력)

활성 디스플레이 목록이 **완전히 비면** 그것은 위험 상황이 아니라 **잠자기**다.
진짜 위험 상황에서는 위처럼 가상 디스플레이가 생겨서 목록이 비지 않는다.

이 구분을 놓치면 잠든 맥을 상대로 복구를 무한 반복하게 된다. 실제로 그런 적이
있고 대가가 컸다 — 실패한 커밋 호출이 **10초씩 블로킹**되는데 그것을 12초마다,
시간당 300회씩 3시간 넘게 반복하며 밤새 배터리를 태웠다. 그래서
`guard !activeDisplays().isEmpty` 가 모든 판단의 첫 관문이다.

덧붙여 복구가 연속 실패하면 지수적으로 물러선다(최대 60초). 고칠 수 없는 상황에서
같은 호출을 반복하는 것은 전력 낭비일 뿐이다.

평상시 폴링은 5초 주기에 여유 2초로 둔다. 실제 감지는 재구성 콜백이 켜는 0.1초
경계 모드가 담당하므로 폴링을 촘촘히 할 이유가 없고, 여유를 크게 줘야 커널이
깨우기를 묶어 처리해 전력을 아낀다.

### 꺼진 내장 디스플레이를 다시 찾는 법

논리적으로 끈 디스플레이는 `CGGetActiveDisplayList` 는 물론 **`CGGetOnlineDisplayList`
에서도 사라진다.** 그래서 목록 열거만으로는 복구할 ID를 알아낼 수 없다 — ID를 캐시해둔
인스턴스가 죽으면 되살릴 방법이 없어진다.

다행히 ID 자체는 살아 있어서 개별 조회에는 응답한다. 그래서 ID 공간(1...64)을 훑어
내장 디스플레이를 찾는다. 유효하지 않은 ID도 `CGDisplayIsBuiltin` 에 true 를 돌려주므로
그것만으로는 구분되지 않고, **vendor 번호(0xFFFFFFFF 가 아님)와 픽셀 크기(0 이 아님)**
까지 확인해야 실제 패널을 가려낼 수 있다.

덕분에 앱을 새로 실행하기만 해도 이전 인스턴스나 다른 앱이 꺼둔 내장 디스플레이를
찾아서 복구할 수 있다.

참고: Lunar 개발자가 시도했던 `SLSDisplayPowerControlClient`(powerd가 쓰는 진짜 클램쉘
트리거)는 Apple 전용 entitlement가 필요해서 서드파티 앱에서는 사용할 수 없다.
([리버스 엔지니어링 글](https://alinpanaitiu.com/blog/turn-off-macbook-display-clamshell/))

## 주의

- **Lunar / BetterDisplay와 동시 사용 금지**: 같은 디스플레이를 서로 제어하려고 하면
  충돌한다. 이 앱을 쓸 때는 해당 앱의 disconnect/BlackOut 기능을 꺼둘 것.
- 비공개 API이므로 macOS 메이저 업데이트 후에는 동작 확인이 필요하다.
